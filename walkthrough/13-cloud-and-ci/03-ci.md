# 03: Continuous integration

**File:** `.github/workflows/ci.yml`

## On every push and pull request (minutes)
| Job | Checks |
|---|---|
| `python` | ruff lint + format, mypy --strict, all unit tests with the 80% coverage gate. No network, no API keys: LLM answers replay from the committed cache, models are faked |
| `frontend` | ESLint and a production Next.js build |
| `infra` | `terraform fmt -check` and `terraform validate` |

## On main, weekly and on demand (~1 hour): `pipeline-and-docker`
1. **Rebuild everything from the regulators' websites**: crawl (with a cache, to be polite),
   parse, time model, serving index, router. LLM steps replay the committed cache, so it's
   deterministic and free.
2. **Quality gate**: re-run the retrieval ablation for the production row and compare it with
   `evals/baseline.json`. If recall@10, nDCG@10 or MRR drop by more than 3 points, or a stale
   (superseded) passage appears in the top 5, **the build fails**. A parser change that quietly
   breaks paragraph numbering is caught here.
3. Build both images, scan the API image with **Trivy** (critical/high CVEs reported).
4. Start the compose stack and run the **smoke test**: health, auth, corpus loaded, cited
   answer, SSE stream, injection refused, repealed rule marked superseded, console proxy.

## Why the weekly rebuild?
Regulators edit their websites. A weekly fresh crawl catches broken parsers (a changed HTML
layout) before a user does, and the quality gate turns "the numbers in the README" into a
contract the code must keep.
